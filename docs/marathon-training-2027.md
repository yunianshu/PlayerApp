# 2027 厦门马拉松训练计划

目标比赛：2027-01-10；日历范围：2026-10-23 至 2027-01-10（80天）。暂定5小时15分，破5仅作挑战目标。

## 已接入
- 首页「2027厦门马拉松训练计划」入口
- 内置80天日期、训练类型、距离、参考配速和训练说明
- 每日训练手动完成标记，持久化本地 SharedPreferences
- 已有跑步记录按本地训练日期汇总显示为「已记录公里数」，但**不会自动标记完成**
- 每日疼痛(0–10)和疲劳(0–10)记录，达到风险值显示调整建议，不自动增加跑量
- Android 系统训练提醒：页面打开右上角通知图标设置时间；打开提醒开关后注册所有未来训练日（含休息日），修改时间会替换旧提醒，关闭会取消
- Android 闹钟使用 AlarmManager.setAndAllowWhileIdle，不需要精准闹钟权限。系统可能延迟派发，**不保证严格精确到分钟**；BOOT_COMPLETED、MY_PACKAGE_REPLACED 恢复待触发提醒
- Android 13+ 首次启用提醒时申请通知权限；若拒绝则不会显示通知，需去系统设置授权
- 鸿蒙系统训练提醒：先等待通知授权，再注册一条每日重复的日历代理提醒；从下一个有效训练时间开始，在本期计划最后一天 23:59:59 结束，覆盖休息日，不会无限重复
- 鸿蒙定时通知文案为“打开跑迹查看今天的马拉松训练计划”，不是每天动态公里数。完整任务仍在训练页。此方式避免80天逐条注册超过系统数量上限
- 鸿蒙仅替换训练提醒保留的通知ID，清理旧版残留；替换或关闭失败时尽量恢复旧提醒，恢复失败明确报告状态不确定。启用状态/时间仅在原生确认成功后一起保存
- 鸿蒙打开训练页后的即时补充通知只在当日设定时间之后、计划日期内触发，发送成功才记录当天去重；这不是后台定时提醒的替代品
- 数据全部保存在本机，不依赖服务器

## 已知平台差异及未完成项
- 原生系统提醒已接入 Android 和 HarmonyOS；iOS 暂不支持
- 鸿蒙手机的代理提醒还受AGC开放能力和签名Profile管控。模块权限声明不代表已获得权益；通知授权、权益、HAP签名和真机结果需分别核验。本修复不申请权益、不修改签名
- 系统错误码保留到提示中：1700001/1600004表示通知未授权，201表示代理提醒权限校验失败，1700002表示数量超限。不能把所有失败都归因于手机通知开关
- 训练日历与完成记录、疼痛疲劳反馈还未纳入应用既有 JSON 备份导出
- 已有跑步只按日期汇总，同日多次跑步也会汇总；仍由用户确认完成；暂不做跑步与任务的强制一对一自动关联
- 疼痛、疲劳反馈只提供安全建议，不会未经确认修改训练计划
- 尚需 Flutter SDK 本地及 Android 真机验证；CI 必须跑 flutter analyze/test

## 测试与验收
在 app 目录运行：
```sh
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
```
安卓真机必须验证：授权/拒绝通知权限、锁屏触发、同一天提示、修改时间、关闭提醒、重启及更新后恢复、错过时间不补发、通知点击打开 App、跑步记录按日汇总、记录反馈及卸载重装。

本计划是可调整建议，不是强制训练处方。持续疼痛或影响步态时应暂停训练并评估。

## 鸿蒙提醒专项验证

官方API依据：[华为代理提醒指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/agent-powered-reminder)、[OpenHarmony提醒API](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-backgroundtasks-kit/js-apis-reminderAgentManager.md)。daysOfWeek 自API11、endDateTime 自API12可用，工程最低兼容API12；仍需实际HarmonyOS SDK构建验收。

```sh
# 在 app 目录；Node 24行为测试剥除类型，不是ArkTS编译
node --test tool/tests/training_reminders_native_test.mjs
flutter test test/training_reminder_service_test.dart
flutter analyze
```

原生模拟测试覆盖授权等待/拒绝、旧提醒迁移、替换与关闭失败回滚、超期拒绝、并发开关、失败重试。Dart测试覆盖80天合并、结束日期、保存失败时不误开启、时间修改失败保留设置、即时通知成功才去重和Android协议兼容。

真机必须验证：
1. 首次点击开关，允许/拒绝通知时分别正确注册或显示原因；拒绝后手动授权再试。
2. AGC能力未开通或Profile缺权益时，展示原生错误码，不假报已开启。
3. 设置未来几分钟，退出应用、锁屏以及结束进程后观察通知；点击通知能打开跑迹。
4. 重复开启、改时间、关闭、升级旧版残留均不重复提醒；关闭不弹权限请求。
5. 测试用短计划验证结束日最后一次提醒后，次日不再触发。
6. 在设备上执行HAP构建及安装验证；Node/Dart测试通过不能证明系统投递、签名权益或锁屏可见已通过。
