# 跑步记录与训练成果

## 单一事实来源

训练成果由已保存的跑步数据库记录和当前计划任务实时推导，不另存自动完成标记。保存、补录、导入、编辑、删除和应用恢复触发 AppData 刷新后重新读取；异步加载带版本号，较旧请求不得覆盖新快照。手动完成仍使用原有按计划隔离的存储，自动核对不会写入或删除手动标记。

同一天多次跑步累计后核对任务距离。按数据库 ID、会话 ID 去重；对于 GPS 记录与其 GPX 重导，开始、结束、距离、运动时长完全一致时只计一次。不同格式导入如果改变这些数据，不能可靠断定是同一活动，不做模糊去重。数据库本身也阻止重复会话导入。现有 RunRecord 数据表只表示跑步，不含其他运动项目；未来加入骑行等活动时，应先增加运动类型并在汇总前过滤。

## 日期和计划边界

以跑步开始时间在设备当前本地时区的日期归属，和现有历史页/运动日历保持一致。跨午夜跑步全部归开始日，不拆分、不按结束日归属。旧记录只有时间戳，没有采集时区，切换设备时区后会按当前时区重新归日。

每份计划仅用自己的任务日期和目标距离推导，计划外日期不产生训练成果。同日期的历史跑步可以为重叠的不同计划提供同一事实，但各自比较各自目标；手动完成绝不跨计划复制。没有记录不等于漏训。

## 距离核对

- 有效正距离跑步任务：实际距离大于或等于计划距离，显示“距离已达标”；小于计划距离则显示部分完成、少跑多少。
- 比较不设完成容差；不足 0.005 km 的差异显示“少跑 <0.01 km”而不四舍五入为完成。展示保留两位小数，判断始终用原始数值。
- 没有记录与记录为 0 分开表示；缺失、负值和非有限值不伪造为达标。
- REST、STRENGTH、CROSS 和零距离任务不因当日跑量自动完成。比赛日可以核对距离，但距离达标不代表配速、强度、动作质量或比赛结果达标。
- 手动完成独立保留，实际不足仍显示少跑。手动标记可以撤销；已经由真实记录达标的状态只能通过记录变化重新推导，不能勾掉真实跑量。

单日卡片、本周一览和月历使用同一结果模型。窄横屏月历只展示状态，完整对比保留在无障碍描述及点击后的日卡。AI 调整发送最近 28 天的按日真实跑量和任务核对结果，并明确区分手动完成；仍需用户确认发送、预览后确认计划，不自动增量或改计划。
