# 主题桌面图标（实验验证）

## 使用

“我的 → 通用设置 → 桌面图标跟随主题”，默认关闭。
开启后，使用当前白天、夜间、编辑风主题的图标；关闭恢复原始图标。
原 Logo 的路线、起点与终点形状保留，只改变背景和强调色。
不改变应用主题色，也不替换系统启动画面。

自动主题在应用运行期间及返回前台时同步。应用完全退出后不运行定时任务，
不能承诺在 6:00 / 19:00 准时更换桌面图标。

平台拒绝切换时保留已保存的开关状态，并尝试恢复之前图标；应用内主题不回退。
若系统拒绝恢复，设置页明确显示状态未能确认，返回应用时会再次核对。

## Android

- 默认启动入口为轻量转发 Activity；三个主题入口为 activity-alias。
- MainActivity 永久保持启用。训练提醒的显式 Intent 直接指向 MainActivity，
  不存储之后可能被禁用的别名。
- Android 13+ 通过批量组件状态 API 切换；更早系统先启用目标，再关闭旧入口。
- 稳态只保留一个桌面入口。失败时先恢复原启用入口，再移除多余入口。
- 桌面刷新、首次升级时已有快捷方式的位置由厂商 Launcher 决定，不能保证瞬间变化或原位保留。
- 切换成主题图标后，部分 Flutter CLI 仍会尝试启动已禁用的默认入口。
  开发调试时先恢复默认图标，或执行
  `adb shell am start -n com.runtrail.runtrail/.MainActivity`。

## 鸿蒙

标准构建不引用新 SDK 符号，明确返回“不支持”，不会假装换图标成功。
API 26 实验构建路径、SDK 检查和步骤见 [鸿蒙开发文档](harmonyos.md)。
运行中的设备支持与编译 SDK 支持都必须检查，不能仅凭“鸿蒙 7”版本名称判断。

## 验证边界

自动化覆盖：默认关闭、启用/关闭持久化、三主题同步、恢复启动、快速重复操作、
进行中主题变化、平台失败回滚、缺失桥接、返回前台重同步及不支持时禁用开关。
Android XML/Manifest 的资源与入口结构另有源码守卫测试。

这些测试不等同于真实 APK/HAP 编译和桌面测试。本次云环境无 Android SDK、
DevEco/HarmonyOS SDK、真机，原生编译与下列操作仍须验证：

1. 旧版本覆盖升级，确认可启动、快捷方式可用。
2. 三种主题轮换、关闭开关、连续点击后桌面最终只有一个正确入口。
3. 退出、重启、跨昼夜后进入应用，核对图标和开关。
4. 从桌面、最近任务、已安排的每日训练提醒进入应用。
5. 图标切换失败时，确认应用内主题正常且可恢复默认图标。
