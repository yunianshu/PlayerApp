# AI 马拉松计划与调整

## 用户流程

训练计划右上角“我的训练计划 · 添加赛事” → 添加赛事 → 填赛事名称、比赛日期、完赛/成绩目标、最近 4 周平均周跑量和最长单次跑、可选 10 公里成绩、恢复情况、每周可训练日。现支持全马与 28–365 天备赛窗口，日期不足不会虚构准备程度。

复用 AI 服务设置的 HTTPS 接口、模型和安全保存的 API Key。每次明确展示接收端、模型、所发字段和费用可能性；用户同意后才发送。GPS 轨迹不发送。模型响应必须是逐日结构化 JSON，通过本地校验后才展示预览；保存与生成是两个独立动作。没有确定性计划伪装成 AI 的回退。

保存的新计划不自动启用。目录保留厦马及其他计划，显式切换当前计划；完成状态、反馈及调整历史按计划隔离。提醒只针对当前计划，切换前取消旧提醒。保存成功但提醒同步失败会单独提示，不将其误报为计划保存失败。

“AI 调整计划”不要求先产生本地调整建议。读取实际跑步记录和最近 28 天疼痛/疲劳反馈，以当前计划为基线生成未来未完成任务建议。预览逐日原/新类型、距离、配速和说明，确认后保存。今天、过去、已完成和比赛日不可改写。计划版本、完成状态、反馈或跑步记录变化会使建议过期。取消或离页不保存；取消等待不保证撤销已发出的服务请求或费用。

## 校验与边界

- 日期完整覆盖，严格日期格式，跨年可用；比赛日唯一且全马 42.195 km。
- 跑量/配速须有限且单位一致；休息/力量任务不包含跑量和跑步配速。
- 根据实际近期基础限制起始量和递进量，限制单次长跑和高负荷间隔，安排休息与赛前减量。
- 恢复欠佳降低起始上限；有疼痛不自动生成跑步处方。低基础、短周期或明显不现实目标明确警示。
- 调整不做递进加量或更快配速，不为遗漏训练补跑。允许的重排仍受原周负荷、恢复和可训练日限制。
- API 不可用、超时、响应过大、JSON 不合法或计划不合规时失败，不保存。
- 所有阈值是产品保守护栏，不是临床认证，不保证防伤、完赛或成绩。

## 原则来源

查阅于 2026-10-23。仅参考一般原则，没有复制第三方训练表。

- Boston Athletic Association：[官方训练说明](https://www.baa.org/races/boston-marathon/info-for-athletes/boston-marathon-training/)，强调渐进训练、恢复/减量与按能力选择计划，且声明其不是医疗建议。
- NHS：[跑步伤痛指导](https://www.nhs.uk/live-well/exercise/knee-pain-and-other-running-injuries/)，疼痛时停止跑步，充分恢复后再开始，必要时寻求专业评估。

具体 10% 周量增长上限、32 km 单次上限、28 天最短输入窗口及疼痛记录阻断窗口是本产品的保守限制，不宣称这些来源验证了精确数字或个人安全性。

## 验证方式

单元/组件测试使用合成数据和假传输，覆盖生成/调整解析、格式与负荷拒绝、跨年、超时、发送确认、取消迟到结果、预览后保存、多计划隔离、过期拒绝和受保护日期。三主题预览由 Flutter 实际渲染，模拟结果明确标注。

未调用真实模型、未上传真实健康数据；本环境没有完成鸿蒙 SDK/HAP 打包和真机通知验证。Harmony 凭据桥接仅执行现有 mock 测试，不能替代真机安全存储和提醒验证。

## 三主题界面

新建、审阅和调整对比共用局部设计组件 `ai_plan_design.dart`，从当前主题设置取现有 AppPalette，不新增或替换全局配色。白天保留玻璃感卡片，暗色采用珊瑚橙运动强调，编辑风采用奶油纸面、墨色文字与荧光绿点缀。日期选择、弹窗、输入焦点、按钮与选择控件使用同一局部主题。

新建页按目标赛事、当前能力、训练节奏三步引导，返回上一步保留输入；审阅页以真实计划逐日数据汇总周跑量趋势与周日程，不虚构模型未提供的训练阶段，确认保存栏独立固定；调整页给出实际变更日期、受影响周的完整原/新跑量、逐日原安排与建议及原因。所有重要风险说明保留。组件支持减少动画，窄屏大字体改为纵向布局。测试覆盖 320px/200% 字体、键盘遮挡、取消/系统返回与主题切换时输入状态。
