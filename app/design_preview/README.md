# 跑步教练设计概念（未接入 App）

这一目录只包含独立的静态 Flutter 设计稿。它不被生产页面导入，不发送 AI 请求，也不读写训练记录。界面按钮只表达设计意图，并非已实现交互。

## 设计路线

1. 创建：将赛事、能力、节奏分成三步。此稿展示第二步，周跑量是主要问题，最长跑距和近期成绩为次要输入。减少容器，利用字重、数字与细分隔线建立优先级。
2. 审阅：先看赛事、目标和首周跑量，再看阶段条与逐周跑量趋势，最后看第一周安排。不再用十几个相同数字方块代替趋势。阶段条是视觉示意，不代表当前 AI 模型已经支持阶段数据。
3. 调整：用周总量和两项逐日差异说明变化。恢复影响只描述安排事实，不宣称医疗收益。保留确认/取消及既往记录保护信息。

沿用 core/theme.dart 的三套真实 AppPalette：浅色清透、暗色运动、奶油编辑风。相同布局使用不同材料与强调色，没有新增配色，没有巨大宣传头图或英文步骤标签。

所有赛事、日期、成绩、反馈及跑量均为合成示例；不是个性化训练建议，不是实际 AI 输出。周图刻意演示渐进、恢复周与赛前减量，不能作为已通过训练校验的计划。调整示例为周总量 36→28 km，两个变更 8→6 km、18→12 km，差值相符。
